Guides

Animation sequences

Run ordered, image-aware animation nodes with controlled timing, transitions, callbacks, and looping.

A sequence controls one renderer. Each node selects a mode, duration, optional delay, image-source action, mode-repeat policy, option overrides, and lifecycle callbacks. The web utility displays nodes left to right in playback order; its image selector can retain the current source, clear it, or load one of the included images.

repeat and sequence loop control different boundaries. A step with repeat: true restarts a finite mode such as fadeIn, fadeOut, irisIn, dissolveOut, or typewriter while that step remains active. It defaults to false, so a finite mode reaches its final frame and holds it until the next step. Sequence loop controls whether playback returns to the first step after the final step.

An incoming step can also declare a morph transition. asciiam captures the outgoing frame once, starts the incoming mode, and fades the captured frame over it. Only the incoming algorithm remains live, so the transition does not run two animation modes concurrently. The default transition is cut; reduced-motion preference also resolves morphs to cuts.

Configure the requested flow

The following sequence runs ripple for five seconds, fades out, fades in, and repeats.

app.js

animation.setSequence([
  { mode: 'ripple', duration: 5 },
  {
    mode: 'fadeOut',
    duration: 5,
    repeat: false,
    transition: { type: 'morph', duration: 0.8, easing: 'easeInOut' }
  },
  {
    mode: 'fadeIn',
    duration: 1,
    transition: { type: 'morph', duration: 0.8, easing: 'easeInOut' }
  }
], {
  loop: true,
  autoplay: true,
  onStepStart(detail) {
    console.log(detail.index, detail.step.mode);
  }
});

Move between images

Set image to a URL to decode and sample a new source before that node starts. Omit the field to retain the current source, or use null to clear image data and return to a procedural grid. A node’s delay elapses first; its duration does not begin until the new image is ready. This prevents decode time from shortening the visible node.

animation.setSequence([
  { mode: 'fadeIn', image: '/media/product-front.webp', duration: 3 },
  {
    mode: 'lumaFold',
    image: '/media/product-detail.webp',
    imageOptions: { animated: false },
    duration: 4,
    transition: { type: 'morph', duration: 0.6, easing: 'easeInOut' }
  },
  { mode: 'wave', image: null, duration: 2 }
], { autoplay: true, loop: true });

animation.on('sequenceStepError', ({ index, error }) => {
  console.error(`Image for node ${index + 1} could not be loaded`, error);
});

An image failure pauses the sequence, calls the node’s optional onError, and emits sequenceStepError. Correct the source or seek to another node before resuming.

delay staggers the start of a step. During the delay, the prior frame state continues. duration begins after the delay completes.

Sequence state

stateDiagram-v2
  [*] --> Configured: setSequence()
  Configured --> Waiting: playSequence() + delay
  Configured --> Playing: playSequence()
  Waiting --> Loading: node declares a new image
  Loading --> Playing: image decoded and sampled
  Loading --> Paused: image error
  Waiting --> Playing: delay elapsed, image retained or cleared
  Playing --> Waiting: next step has delay
  Playing --> Playing: next step
  Playing --> Paused: pauseSequence()
  Paused --> Playing: playSequence()
  Playing --> Complete: last step and loop=false
  Playing --> Configured: stopSequence()
  Playing --> Interrupted: manual setMode()

Callbacks and events

Step callbacks receive (detail, animation). The same lifecycle is available through on() event subscriptions when configuration should remain serializable.

API reference

setSequence(steps, options)step array, sequence optionsConfigures a sequence and returns the instance.
playSequence(index?)optional start indexStarts or resumes playback.
pauseSequence(reason?)optional reasonPauses at the current step.
