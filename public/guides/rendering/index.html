Renderers and performance

Select WebGL2 or Canvas 2D and control quality, frame rate, memory, and multi-instance behavior.

asciiam separates animation-state calculation from presentation. WebGL2 uploads one glyph instance buffer and draws the visible glyphs as instanced quads. Canvas 2D uses cached glyph atlases and mode-specific shortcuts where possible.

Renderer selection

app.js

const animation = new asciiam('#target', {
  renderer: 'auto',
  powerPreference: 'high-performance',
  quality: 'ultra'
});

auto is appropriate for most integrations. Use canvas2d for deterministic CPU rendering or environments that limit WebGL contexts. Use webgl2 when the requested renderer must be recorded as GPU-first while retaining fallback behavior.

WebGL2 fallback flow

flowchart TD
  A[Construct instance] --> B{renderer}
  B -->|canvas2d| C[Canvas 2D]
  B -->|auto or webgl2| D{WebGL2 context and shaders available?}
  D -->|yes| E[Instanced WebGL2 renderer]
  D -->|no| C
  E --> F{Context lost?}
  F -->|yes| C
  F -->|no| E

The rendererFallback event reports context-loss fallback. rendererChange reports a requested or resolved backend change.

Higher density values produce fewer cells because they increase cell spacing. targetFPS: null does not impose a library frame cap; the browser display and scheduler remain the physical limit.

Logical grid resolution

Browser zoom changes the CSS-pixel size reported by the target, so the automatic column and row count changes with it. resolutionScale provides an explicit adjustment without changing canvas DPR:

app.js

const animation = new asciiam('#target', {
  resolutionScale: 0.75
});

1 retains automatic sizing. 0.5 produces the coarsest supported grid and reduces cell work. 2 produces the finest supported grid. Glyph size and cell spacing change together, so the grid remains contiguous. The option applies to procedural animation, images, GIF frames, and 3D meshes. On a fixed-size surface, cell count grows approximately with the square of the scale; test values above 1 on the intended device class.

Diagnostics

showStats: true retains the compact FPS, grid, and drawn-cell line. Add extendedStats: true to measure and display:

  • estimated active display cadence from raw requestAnimationFrame intervals;
  • resolved renderer, quality tier, and effective DPR;
  • mean CPU-side asciiam frame work with a 24-sample text sparkline;
  • drawn-cell occupancy with a 24-sample text sparkline;
  • WebGL adapter text when the browser permits WEBGL_debug_renderer_info;
  • vertex, primitive, topology, raster style, and model state for active 3D input.

requestAnimationFrame generally follows display refresh, but browsers do not expose a portable hardware refresh-rate property. The reported Hz value is therefore an estimate and is reset after visibility suspension. WebGL adapter strings can be unavailable under browser privacy controls. The fill chart reports submitted or drawn ASCII-cell occupancy; it is not GPU utilization. CPU utilization and GPU utilization percentages are not reported because the required portable browser APIs do not exist.

Extended diagnostics allocate their fixed history lazily and sample performance.now() only while both statistics flags are active. Output changes at most every 500 ms. They do not install a polling timer, PerformanceObserver, GPU timer query, or dependency. Run npm run benchmark:stats after changing this path.

Browser references: requestAnimationFrame cadence, WEBGL_debug_renderer_info privacy behavior, and the limited-availability WebGL timer-query extension.

Multiple instances

All running instances share one requestAnimationFrame scheduler. Each instance retains independent timing, visibility, renderer, and target state. For galleries or grids, construct only visible previews and destroy off-screen instances after a short delay. Browsers limit the number of simultaneous WebGL contexts.

3D rendering boundary

The mesh mode projects bounded geometry into cell-resolution depth and luminance buffers, then uses the existing WebGL2 or Canvas 2D glyph presentation path. It does not turn the WebGL2 backend into a general scene renderer. See 3D meshes and models for geometry contracts, glTF/GLB input, controls, and limits.

Poly Haven models are recorded as a CC0 candidate source for optional demonstrations. Khronos glTF Sample Assets are recorded for format fixtures, with per-model license verification required. The glTF 2.0 specification is the format reference for core .gltf and .glb input. Base-format parsing is dependency-free; codecs for compressed extensions are not bundled, loaded, or injectable. Files requiring those extensions will fail with a format diagnostic.
