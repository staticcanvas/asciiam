001 — Introduction

What is AETHER?

AETHER is a large language model API built for production. It exposes a unified interface over multiple model families, handling the infrastructure complexity so you can focus on capability — not plumbing.

This documentation covers the full surface area of the API. Every endpoint, every parameter, every failure mode. It was written to be actually read, not just referenced in a panic at 2am.

002 — Quickstart

First request in
under 60 seconds.

Install the SDK, set your key, send a message. That's the whole loop. Every other concept in this documentation is variation on this core pattern.

Install

Terminal 
# npm
npm install @aether/sdk

# pnpm
pnpm add @aether/sdk

Send a message

TypeScript 
import Aether from '@aether/sdk';

const client = new Aether({
  apiKey: process.env.AETHER_API_KEY
});

const message = await client.messages.create({
  model: 'aether-4-opus',
  max_tokens: 1024,
  messages: [
    {
      role: 'user',
      content: 'Explain quantum entanglement.'
    }
  ]
});

console.log(message.content[0].text);
Note
Store your API key in environment variables. Never commit credentials to source control. Use a secrets manager in production environments.
003 — Messages API

The messages
endpoint.

The messages endpoint is the core of AETHER. Send a list of messages, receive a response. The model is stateless — every request is complete and self-contained. You own the conversation history.

POST /v1/messages

Request Parameters

Parameter Type Status Description
model string Required Model identifier. See model reference for available values.
messages array Required Alternating user/assistant message array. Must begin with a user message.
max_tokens integer Required Upper bound on output tokens. Does not guarantee this length.
system string Optional System prompt. Sets context, persona, and behavioral constraints.
temperature float Optional Sampling temperature 0–1. Higher = more variation. Default: 1.0.
stream boolean Optional Enable SSE streaming. Returns incremental tokens as they generate.
tools array Optional Array of tool definitions. Enables function calling behavior.
Warning
Setting temperature above 0.8 on structured output tasks significantly increases malformed JSON. For deterministic extraction, use 0.0–0.2.
004 — Tool Use

Extend the model
with functions.

Tools let AETHER call your code. Define function schemas, the model decides when to invoke them, you execute and return results. The model completes its response using the data you provided.

TypeScript 
const response = await client.messages.create({
  model: 'aether-4-sonnet',
  max_tokens: 1024,
  tools: [
    {
      name: 'get_weather',
      description: 'Fetch current weather for a city',
      input_schema: {
        type: 'object',
        properties: {
          city: {
            type: 'string',
            description: 'City name'
          }
        },
        required: ['city']
      }
    }
  ],
  messages: [{
    role: 'user',
    content: 'What is the weather in Tokyo?'
  }]
});

Tool execution lifecycle

01 — Request
Send messages array with tool definitions. Model receives full context including schemas.
02 — Decision
Model decides whether to call a tool or respond directly. Returns a tool_use content block.
03 — Execution
Your code executes the function. The model has no access to the execution environment.
04 — Result
Return a tool_result block in a new request. Model completes its response with your data.
