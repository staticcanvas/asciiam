- [x] 🟠🌟✅3️⃣ **Engineering Backlog** - **Real per-cell morph transitions (2026-08-26).** The sequence `morph` transition was a whole-canvas crossfade (an offscreen `<canvas>` snapshot faded via CSS opacity) — no ASCII cell ever changed character, only a flat image dissolved into another. Replaced with an actual per-cell transition across all 32 built-in modes and all 3 render backends, with zero renderer-specific code.
  > **Solution Implemented:** Renamed the original whole-canvas crossfade from `type: 'morph'` to `type: 'blend'`. `'morph'` now captures the outgoing frame's cells (char/opacity/level/bold/fully-resolved color) into a pooled `cols*rows` buffer — CPU-side only, reusing the active mode's existing dense/sparse/mesh compute loop, no canvas or GPU pixel readback — then blends each cell's captured "before" state against the live "after" state every real paint frame, inside `_paintCell`/`_paintResolvedCell` (the single choke point already shared by Canvas 2D, WebGL2, and WebGPU). Per-cell transition timing reuses the exact staggered-wavefront math `assemble`/`breakApart`/`_dissolveCell` already use (`_seedCache`/`_revealProgress()`) — no new noise or state. Three selectable `style`s: `'dissolve'` (default; a cell crossfades in place, two paint calls only for cells currently inside the thin wavefront band), `'scramble'` (a cell flickers through a few charset glyphs via a deterministic hash before settling, no extra paint calls), `'flow'` (cells with a matching character within a small search radius slide from their old position to their new one; matching runs once at transition start, not per frame, and is capped at 20,000 cells). Falls back to `'blend'` automatically for cases that can't be captured cell-by-cell: an active `setLayers()` composite (no single per-cell color once layers blend at the pixel level), a step whose own `options` resize the grid mid-transition, or while a step's image/model source is still loading. Steady-state cost outside a transition is unchanged (one falsy property check per cell); in-transition cost measured at 0.10–0.39 ms/frame across wave/matrix × all 3 styles at 100×27 cells in the Node/JSDOM Canvas 2D benchmark harness, against the existing 4 ms/8 ms desktop gates. Six new Jest tests cover the `blend` rename, real per-cell character change, each of the three styles' distinguishing behavior, and the `setLayers()`/grid-resize fallback. `docs/static/webutil/js/webutil.js`'s sequence editor and `webutil-sequence.js`'s normalizer were updated to expose and round-trip `blend` (previously unreachable from the UI after the rename) alongside `morph`; a full style/spread picker UI is a follow-up, not built in this pass. README, the API reference, the Animation sequences guide, and `architecture/runtime.md` updated; changelog entry added under Unreleased with an explicit behavior-change callout for existing `type: 'morph'` configs.

  Standard, MDN WebGPU API guidance, and Chrome WebGPU browser-support/troubleshooting notes.

  ASCII-art generation tool for static output.
